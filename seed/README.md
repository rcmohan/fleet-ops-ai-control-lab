Synthetic master data as CSV, one file per entity. Column names are the API field names; list columns separate values with `;`; an empty cell is null.

| --- | --- | --- |

The `*_golden*` rows are the pinned records the demo story uses: Northstar Synthetic Logistics (`flt_golden`), vehicle `veh_golden_001` with unit `tcu_golden_001`, provider `sp_golden_east`, and two prior battery incidents.

## Load

With the stack running:

```powershell
python -m fleetops_seed load                 # seed/seed-v1 through http://127.0.0.1:8080
```

Records go through the public APIs in dependency order (providers, fleets, units, vehicles, maintenance, incidents), so every reference and business rule is checked as it would be for any client. Loading again is safe: rows that already exist are counted as existing and left unchanged. To load changed rows, start from empty databases (`docker compose down -v`).

## Regenerate

`seed-v1/` is generated by `fleetops_seed/catalog.py`, deterministically: the same seed version and sizes always give the same files.

```powershell
python -m fleetops_seed generate                                  # rewrites seed/seed-v1
python -m fleetops_seed generate --vehicles 2000 --out seed/large  # a bigger set elsewhere
```

A test fails if `seed-v1/` no longer matches the generator, so change the generator and regenerate rather than hand-editing `seed-v1/`. For hand-made data, copy the folder and edit the copy, then `load --data <folder>`.
